1. RESUM I PROPÒSIT DEL PROJECTE
-------------------------------------------------------------------------------
El projecte "FormFriends-Posts" és un sistema d'automatització d'extrem a extrem 
(End-to-End Automated Content Pipeline) dissenyat per generar carrousels gràfics 
personalitzats de 7 diapositives i publicar-los automàticament a INSTAGRAM i TIKTOK 
de manera simultània a través de la GraphQL API de Buffer.

A més, el sistema gestiona l'estat del contingut en un fitxer CSV local, realitza 
commits automàtics a GitHub i envia notificacions de confirmació en format HTML 
a un canal/grup privat de Telegram amb la imatge de portada adjunta.

3. ARQUITECTURA I FLUX D'EXECUCIÓ (STEP-BY-STEP PIPELINE)
-------------------------------------------------------------------------------
Cada execució del workflow (`python generate_and_send.py`) segueix rigorosament 
el següent flux lineal:

[Passor 1: Gestió de Fonts i Lectura de Dades]
 - Es comprova la presència de les fonts Poppins-Bold i Poppins-Regular; si no hi són, 
   es descarreguen des del repositori oficial de Google Fonts a GitHub.
 - Es llegeix `posts.csv`. El script cerca la PRIMERA línia on la columna 'Status' 
   SIGUI DIFERENT de 'Done' (case-insensitive).
 - S'extreuen el Post_ID, Slide_1_Title i les preguntes de la Slide_2 a la Slide_6.

[Passor 2: Generació Gràfica amb Pillow (PIL)]
 - Es creen 7 diapositives quadrades (1080 x 1080 píxels).
 - Es tria un fons fosc aleatori d'una paleta predefinida (Hex: #101520, #161F2B, etc.).
 - S'hi dibuixa una targeta central blanca translúcida (RGBA: 255, 255, 255, 25) 
   amb cantonades arrodonides (radius=40).
 - Diapositives 2 a 6 (Preguntes): Dibuixa una barra de progrés superior personalitzada.
 - Diapositiva 7 (Call to Action / CTA): Selecciona una CTA aleatòria, empeny el text 
   a la part superior i enganxa el 'mockup.png' (fent servir l'algoritme de calibratge de la secció 4.1).
 - FORMAT D'EXPORTACIÓ: Les imatges es desaven OBLIGATÒRIAMENT en format JPEG (.jpg) 
   amb una qualitat del 95% a la carpeta `public_slides/`.

[Passor 3: Publicació de Mitjans a GitHub Raw CDN]
 - Perquè Buffer i Instagram puguin llegir les imatges, aquestes han d'estar en 
   URLs HTTPS públiques, estables i amb capçalera 'Content-Type: image/jpeg'.
 - L'script executa comandos de Git internament (`git add`, `git commit`, `git push`) 
   per pujar les imatges generades a la carpeta `public_slides/` del repositori.
 - Es construeixen les URLs públiques directes mitjançant la CDN oficial de GitHub:
   `https://raw.githubusercontent.com/{owner}/{repo}/{branch}/public_slides/{filename}`

[Passor 4: Publicació Simultània via Buffer GraphQL API]
 - Es realitzen consultes GraphQL a l'endpoint `https://api.buffer.com`.
 - S'obtenen les organitzacions i canals connectats a Buffer (Instagram i TikTok).
 - S'envia la mutation `createPost` per a cada canal.
 - S'apliquen metadades específiques segons la xarxa social (veure secció 5).

[Passor 5: Notificació per Telegram i Actualització de l'Estat]
 - Si la publicació a Buffer té èxit, s'envia una petició a l'API de Telegram 
   (`sendPhoto`) amb la imatge de portada (`Post_X_slide_1.jpg`) i un missatge en HTML.
 - Es modifica la columna 'Status' de la fila processada a 'Done' a `posts.csv`.
 - GitHub Actions fa el commit final del `posts.csv` actualitzat al repositori.

4. ESPECIFICACIÓ TÈCNICA DE GENERACIÓ D'IMATGES (Pillow)
-------------------------------------------------------------------------------
- Mides: 1080 x 1080 px (Relació d'aspecte 1:1, estàndard per a carrousels).
- Ajust de Text: Funció `wrap_text()` calcula l'amplada dels caràcters fent servir 
  `draw.textbbox()` per tallar línies de forma neta sense partir paraules.
- Format de Sortida: **JPEG / .jpg (Quality=95)**.
  CRUCIAL: Meta Graph API (Instagram Direct Publishing) REBUTJA o descarta carrousels 
  si els fitxers tenen extensió .png o capçaleres MIME de PNG. L'ús de JPEG és 
  un requisit estricte del pipeline d'Instagram.

4.1 RENDERING DE LA SLIDE DE CRIDA A L'ACCIÓ (CTA) I MOCKUP MÒBIL
-------------------------------------------------------------------------------
Per evitar proves i errors de posicionament visual, el rendering de la diapositiva 7 
(CTA) segueix rigorosament les següents regles geomètriques i d'escala:

1. Detecció Tolerant a Majúscules i Extensions:
   - La funció `find_file_case_insensitive('mockup.png')` localitza el fitxer 
     independentment de majúscules o extensions (`mockup.png`, `mockup.PNG`, `mockup.jpg`, `Mockup.png`).
     Això evita errors de tipus 404 en entorns de servidors Linux (GitHub Actions Runner).

2. Neteja de Marges Transparents (`getbbox()`):
   - S'executa `bbox = mockup_img.getbbox()` abans de qualsevol transformació per 
     eliminar qualsevol espai transparent o buit a les vores del fitxer original. 
     Això garanteix que el límit $Y=0$ sigui exactament la línia superior del telèfon.

3. Ràtio de Retall Vertical (Proporció 70%):
   - `mockup_img = mockup_img.crop((0, 0, w_orig, int(h_orig * 0.70)))`
   - Retalla el 30% inferior de la pantalla del mòbil.
   - Propòsit visual: Inclou la Dynamic Island/Notch, la capçalera de FormFriends, 
     la targeta rosa d'Instagram i mostra COMPLETAMENT SENCERES les targetes de "Spicy Questions" 
     i "Ultimate Roast", mentre elimina netament les seccions inferiors ("Politics", "Food", etc.).

4. Escalat Proporcional per Amplada (`target_width = 550px`):
   - `target_width = 550` (píxels).
   - L'alçada es calcula proporcionalment: `target_height = int(h_orig * (550 / w_orig))`.
   - Dins de la targeta central de 920px d'amplada (1080px - 2x80px de marge), 
     això deixa un marge d'aire elegant de 185px a cada costat (esquerra/dreta).

5. Posicionament Mil·limètric (Y = 390px):
   - `mockup_x = int((1080 - 550) / 2) = 265` (Centrat horitzontalment).
   - `mockup_y = 390` (píxels).
   - Motiu: Deixa exactament ~50px de separació neta sota el text "Link in bio", 
     evitant que el telèfon tapi o s'apropi massa al text superior, mentre estén 
     el cos del mòbil fins a la part inferior de la slide.

5. INTEGRACIÓ AMB BUFFER GRAPHQL API (APIs & METADATA RULES)
-------------------------------------------------------------------------------
Endpoint oficial: `https://api.buffer.com`
Autenticació: Header `Authorization: Bearer <BUFFER_ACCESS_TOKEN>`

1. Obtenir Organització:
   Query: `query GetOrganizations { account { organizations { id name } } }`

2. Obtenir Canals de la Organització:
   Query: `query GetChannels($input: ChannelsInput!) { channels(input: $input) { id name displayName service } }`
   Variables: `{"input": {"organizationId": "<org_id>"}}`

3. Crear la Publicació (Mutation CreatePost):
   Mutation: `mutation CreatePost($input: CreatePostInput!) { createPost(input: $input) { ... on PostActionSuccess { post { id text } } ... on MutationError { message } } }`

   REGLES STRICTES DE METADADES SEGONS EL CANAL:
   - Per a Instagram (`service` conté "instagram"):
     S'HA D'INCLOURE OBLIGATÒRIAMENT el camp `shouldShareToFeed`:
     ```json
     "metadata": {
       "instagram": {
         "type": "post",
         "shouldShareToFeed": true
       }
     }
     ```
   - Per a TikTok (`service` conté "tiktok"):
     NO S'HA D'INCLOURE el camp `type` a les metadades (l'esquema GraphQL 
     `TikTokPostMetadataInput` no defineix el camp `type` i la petició fallarà 
     amb un error `INTERNAL_SERVER_ERROR` si s'envia). Es deixa sense `metadata`.

6. SISTEMA D'ALLOTJAMENT D'IMATGES (GitHub Raw CDN & Fallbacks)
-------------------------------------------------------------------------------
Perquè Buffer/Instagram descarreguin les imatges, les URLs han de respondre 
amb HTTP 200 OK a peticions `HEAD` i `GET` sense desafiaments anti-bot (Cloudflare).

Estratègia de Servidors:
1. Primary Host: **GitHub Raw CDN** (`raw.githubusercontent.com`)
   - REQUISIT CRÍTIC: El repositori de GitHub (`rjydly/FormFriends-Posts`) HA DE SER PÚBLIC. 
     Si el repositori és privat, GitHub retorna HTTP 404 Not Found a peticions no 
     autenticades i Buffer no pot llegir els mitjans (`Image could not be read from its URL`).
2. Fallback 1: **FTP Server** (`upload_via_ftp`)
   - Si les variables d'entorn `FTP_HOST`, `FTP_USER`, `FTP_PASS` estan definides, 
     l'script puja les imatges directament al servidor web de `formfriends.com` 
     a la carpeta `public_slides/`.
3. Fallback 2: **ImgBB API** (`upload_to_imgbb`)
   - Utilitza la clau d'API privada `IMGBB_API_KEY` fent POST a `https://api.imgbb.com/1/upload`.

9. GUIA DE DISSOLUCIÓ DE PROBLEMES (TROUBLESHOOTING PER A IAS)
-------------------------------------------------------------------------------
- Error: "Image could not be read from its URL" a Buffer.
  Causa: El repositori és Privat i les URLs de GitHub Raw tornen 404, O bé el 
  servidor d'imatges té protecció anti-bot.
  Solució: Assegurar-se que el repositori sigui PÚBLIC o activar la pujada FTP.

- Error: "Field 'shouldShareToFeed' of required type 'Boolean!' was not provided".
  Causa: S'ha intentat publicar a Instagram sense la metadada obligatòria.
  Solució: Incloure `metadata.instagram = {"type": "post", "shouldShareToFeed": True}`.

- Error: "Field 'type' is not defined by type 'TikTokPostMetadataInput'".
  Causa: S'ha passat `"type": "post"` al canal de TikTok.
  Solució: No enviar el camp `type` a TikTok (omitir `metadata` o enviar-lo buit).

- Error: "Public API tokens are not accepted for REST API access".
  Causa: Intent d'usar l'API REST antiga (`api.bufferapp.com`).
  Solució: Usar l'endpoint GraphQL oficial (`https://api.buffer.com`).

- Error: Els carrousels es publiquen a TikTok però no a Instagram.
  Causa: Format d'imatge PNG o canal d'Instagram configurat com a "Reminders" a Buffer.
  Solució: Assegurar-se que l'script exporti en format `.jpg` (JPEG) i que el canal 
  d'Instagram a Buffer tingui activada la "Direct Publishing".

PIPELINE 1: CARROUSELS D'IMATGES (generate_and_send.py)
Propòsit: Generar i publicar 7 diapositives quadrades (1080x1080 px).
Format d'exportació: JPEG (.jpg, qualitat 95%) per compatibilitat amb l'API de publicació directa d'Instagram (Meta Graph API rebutja fitxers .png).
Diapositiva 7 (CTA): Renderitza un mockup de mòbil a Y=390px, retallat al 70% vertical, centrat horitzontalment a 550px d'amplada per a una composició neta.
Exclusió de YouTube: Com que YouTube no suporta carrousels d'imatges estàtiques, la funció post_to_buffer filtra i omet de manera explícita els canals amb service_name que contingui "youtube" per evitar errors de validació a l'API.
PIPELINE 2: REELS, TIKTOKS I SHORTS DE VÍDEO (generate_and_send_video.py)
El script de vídeo genera una composició vertical de 50 segons de durada a 30 FPS.
4.1 Especificacions de Temps i Estructura:
FPS: 30 fotogrames per segon (Límit de rendiment per a Runners de GitHub Actions: 2 vCPUs i 7 GB de RAM. Un FPS superior, com 60 FPS, excedeix el consum de CPU/RAM).
Durada total: 50.0 segons de vídeo.
Slide 1 (Portada): 5.0 segons.
Slides 2 a 6 (Preguntes): 9.0 segons cadascuna.
Transició / Overlap: 0.5 segons definits per a la fusió de color i canvi de text.
4.2 Lògica de Generació de Fotogrames (Pillow RGBA):
En lloc de delegar el rendiment a MoviePy, tota la generació d'imatges es fa a nivell de codi de manera lineal, afegint els fotogrames resultants a una llista de memòria (all_frames) convertits a matrius NumPy RGB (np.array).
Per a cada Slide i cada fotograma f_idx en el temps t = f_idx / fps:
Fons Dinàmic (Color Merge):
Si t < duration - 0.5: El color de fons és el color HEX de la slide actual (current_bg_hex).
Si t >= duration - 0.5: Es calcula el factor d'interpolació k = (t - t_start) / 0.5. El fons es calcula fent una barreja lineal d'RGB cap al color de la següent slide (next_bg_hex).
Text Dinàmic (Fade In / Fade Out):
El text de les preguntes es renderitza en una capa RGBA independent.
Primers 0.5s: L'opacitat del text puja de 0 a 255 (Fade-In).
Últims 0.5s: L'opacitat del text baixa de 255 a 0 (Fade-Out).
El marc de la targeta translúcida, el nom "FormFriends" i el logo de la marca es mantenen estàtics amb opacitat màxima constant durant tot el clip.
Barra de Progrés Superior:
Fons de la barra (Track): Sempre visible, cantonades arrodonides, fill (255, 255, 255, 70).
Barra que s'omple (Fill): Creix d'esquerra a dreta en funció del progrés t / (duration - 0.5).
En els últims 0.5s de transició de la slide, el progrés es manté fix al 100%, però l'opacitat del seu color blanc disminueix linealment de 255 a 0 (Fade-Out), permetent un reinici net a la següent slide des del 0%.
4.3 Compilació del Vídeo i l'Àudio (MoviePy):
Seqüència: Es crea el clip principal de vídeo a partir de la llista de fotogrames: clip = ImageSequenceClip(all_frames, fps=30).
Workaround d'Àudio: Per evitar el problema del silenci produït per MoviePy en servidors headless (on la fusió directa d'imatge i so no es codifica bé), s'inicialitza l'àudio mitjançant un mesclador multicanal de CompositeAudioClip: clip = clip.set_audio(CompositeAudioClip([audio.set_start(0)]).set_duration(total_duration))
Exportació: Es renderitza el fitxer a 30 FPS fent servir: codec="libx264", audio_codec="aac", temp_audiofile="temp-audio.mp3", remove_temp=True.
SANEJAMENT D'ÀUDIO I SOLUCIÓ DE PROBLEMES DE DESCODIFICACIÓ
Els fitxers descarregats d'internet de vegades tenen capçaleres trencades (per exemple, M4A o WAV rebatejats com a .mp3), la qual cosa bloqueja el demuxer d'FFmpeg amb l'error: Failed to find two consecutive MPEG audio frames.
El script de vídeo implementa una arquitectura defensiva:
validate_audio_file(file_path): Comprova si la cançó té un pes superior a 1KB i que no sigui un fitxer de text de tipus "Git LFS Pointer" (error típic quan no es configura correctament la descàrrega de binaris a GitHub Actions).
clean_and_normalize_audio(input_path, output_path): S'executa FFmpeg des de línia de comandes com a subprocessos per re-codificar l'àudio a un MP3 estàndard amb freqüència de mostreig de 44.1kHz, Stereo i 192kbps abans de ser lliurat a MoviePy. Això garanteix un flux d'entrada òptim i lliure d'errors.
